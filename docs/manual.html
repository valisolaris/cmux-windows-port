cmux(Windows 対応版) 利用マニュアル

Rust 製 TUI マルチプレクサ cmux-tui を Windows 11 で使うための操作ガイドです。本書の内容はすべて Windows 実機で動作確認済みの挙動に基づきます。

1. 起動方法

事前準備(release ビルド済み exe の配置・micro の導入・Windows Terminal プロファイル登録)は完了済みです。次のいずれかで起動します。

A. Windows Terminal の「cmux」プロファイル(推奨)

Windows Terminal の新規タブメニュー(タブ右の ⌄)から cmux を選ぶだけで起動します。内部でランチャ bin\cmux.ps1 を呼び出します。

B. ランチャを直接実行

powershell -NoLogo -ExecutionPolicy Bypass -File <project-root>\bin\cmux.ps1

ランチャは EDITOR=micro をこのプロセス内だけに設定してから cmux-tui.exe を起動します(システム/ユーザー環境変数は変更しません)。micro が PATH に無くても winget のパッケージ配置から版非依存で自動解決します。

✓ 自己完結

bin\cmux-tui.exe は release ビルド済みで、外部 DLL(mingw ランタイム等)に依存しません。PATH が System32 のみでも起動します。

2. 共有セッションモデル

cmux-tui は tmux と同じクライアント/サーバ型です。セッション名ごとに1つのサーバ(ソケット)が対応します。

  • 既定セッション名は main。最初に起動したプロセスが main サーバを立ち上げます。
  • 2つ目以降の起動は、同じ main に「クライアント」としてアタッチします。複数のウィンドウ/タブから開いても全員が同じ画面を共有します(別々の独立画面にはなりません)。
  • ステータス行に接続中のクライアント数(例: 2 clients)と、表示サイズ(例: 120x30 min)が出ます。表示は最も小さいクライアントのサイズに合わせて縮むため、片方のウィンドウが小さいと全体がそれに合わせられます。
  • アタッチを外す(デタッチ)は Ctrl+B → d。サーバとセッションは残り、後からまたアタッチできます。

独立した別セッションを持ちたいとき

--session <名> を付けて起動すると、main とは別のサーバ(別ソケット)になり、独立した画面になります。

powershell -NoLogo -ExecutionPolicy Bypass -File ...\bin\cmux.ps1 --session work

3. ターミナル多重化の基本操作(キー表)

押し方の基本

prefix = Ctrl+B。prefix 経由の操作は、まず Ctrl+B を押して離し、続けて対象キーを押します(tmux と同じ2段階)。

Alt 系はモードレス: Alt+キーは prefix なしでそのまま効きます。大文字表記(X・B・S・W)は Shift 併用の意味です。

4. コード閲覧(sidebar_files → micro)

ファイルサイドバー sidebar_files でフォルダをたどり、ファイルを CLI エディタ micro で開きます。cmux-tui 内で完結します。

手順

  1. サイドバーを開く: Ctrl+B → s(表示されていなければ)。ファイルビューでなければ Ctrl+B → e でビュー切替。
  2. サイドバーにフォーカス: Ctrl+B → Shift+s。
  3. 目的のフォルダ/ファイルへ移動して選択を開く(Enter)。ファイルなら $EDITOR(=micro)が新規ペインで開きます。
  4. micro で編集 → Ctrl+S で保存 → Ctrl+Q で閉じる。

サイドバー内のキー(フォーカスがあるとき・prefix 不要)

キー動作
↑ / Ctrl+k選択を1つ上へ
↓ / Ctrl+j選択を1つ下へ
→選択中のディレクトリに入る
Enter選択を開く(ディレクトリ=移動、ファイル=$EDITOR で新規ペイン)
← / h親ディレクトリへ
.隠しファイルの表示トグル
/フィルタ(絞り込み)モード開始
~表示ルートを再設定(reroot)
c選択ディレクトリへの cd をフォーカスペインへ送る
o選択した .html / .md をブラウザタブで開く

! micro が開かない場合

ランチャ(bin\cmux.ps1)経由で起動していれば EDITOR は自動解決されます。cmux-tui.exe を直接起動すると EDITOR 未設定で vi にフォールバックし Windows では破綻します。必ずランチャ経由で起動してください。

5. HTML プレビュー(o → Chrome)

サイドバーで .html / .md を選び o を押すと、headful Chrome の実ウィンドウにページが表示されます。

手順

  1. サイドバーにフォーカス(Ctrl+B → Shift+s)。
  2. プレビューしたい .html(例 samples\preview-test.html)を選択。
  3. o を押す → Chrome の実ウィンドウが開いてページを表示。

✓ TUI 側の「no kitty graphics」表示は正常

cmux-tui の browser ペイン内には terminal has no kitty graphics support というメッセージが出ますが、これは仕様どおりの正常動作です。Windows Terminal は画像描画(kitty graphics protocol)に非対応で、本構成では画像を TUI 内に出さず Chrome の実ウィンドウに表示する方針です。実際のプレビューは Chrome ウィンドウ側で確認してください。

ローカルファイルは file:///C:/… 形式の URL で開かれます(Chrome のアドレスバーで確認できます)。

6. 設定(cmux-tui.json)

設定ファイルは次の場所です(存在しなければ既定で動作します。作成すると上書きできます):

%APPDATA%\cmux\cmux-tui.json

環境変数 CMUX_TUI_CONFIG で別パスを指定することもできます。

キーバインドの変更(keys セクション)

keys セクションで prefix や各アクションのキーを上書きできます。値は文字列(単一)か文字列の配列(複数割り当て)です。

{
  "keys": {
    "prefix": "ctrl+b",
    "alt_shortcuts": true,
    "new-tab": ["t", "alt+t"],
    "next-tab": "tab",
    "prev-tab": "backtab",
    "browser-edit-url": "u"
  }
}
  • "prefix": prefix キー(既定 ctrl+b)。
  • "alt_shortcuts": false にすると Alt 系モードレスを一括で無効化できます。
  • アクション名(new-tab 等)は「3. キー表」の括弧内の英名と対応します。

補足

設定は起動時に読み込まれます。変更したら cmux-tui を再起動してください。

7. トラブルシュート

症状対処
ファイルを Enter で開いても micro が起動しない ランチャ bin\cmux.ps1 経由で起動しているか確認。直接 exe を起動していると EDITOR 未設定になります。micro 自体が無ければ winget install --id zyedidia.micro -e で導入。
o を押しても Chrome にページが出ない / 真っ白 Chrome がインストールされているか確認。別ブラウザを使う場合は設定の browser.chrome_binary に実行ファイルのフルパスを指定します。詳細な CDP のやり取りを見たいときは bin\cmux-debug.ps1 で起動するとトレースがログに残ります。
browser ペインに「no kitty graphics support」と出る 正常です(「5. HTML プレビュー」参照)。プレビューは Chrome の実ウィンドウ側に表示されます。
起動直後にプロンプトへ [?61;…c のような文字が漏れる windows-port の graphics.rs パッチ(1b5369b)で解消済みです。出る場合は bin\cmux-tui.exe がパッチ適用済みの release ビルドか確認してください。
2つ目のウィンドウを開いたら画面が同じ/サイズが縮んだ 仕様です。同名セッション(既定 main)は共有され、表示は最小クライアントに合わせます。独立させたいときは --session <名> で起動(「2. 共有セッションモデル」参照)。
exe を作り直したい / ビルドを再現したい 環境メモとビルド再現手順(PATH・LIBCLANG_PATH・BINDGEN_EXTRA_CLANG_ARGS・必須の回避策2点)は ROADMAP.md が正です。そちらを参照してください。
