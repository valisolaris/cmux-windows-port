ペイン内タブバー2段表示 — 仕様視覚レビュー(2026-07-26)

spec.md / decisions.md(同ディレクトリ)で確定した配置・挙動のモックアップ。ラベルの中身・区切りの見た目は現行踏襲(タブ名/文字数は別軸)で、本図は配置のみを示す。

1. 通常時(タブが収まる) — 従来どおり1段

┌ t0 │ t1 │ t2 + ───────────────┐
│ content: height = rect.h - 2  │
│                               │
└───────────────────────────────┘

タブが1段に収まる限り現状と完全に同一。+ は最終タブの直後。

2. 2段表示(タブが溢れ、2段で全部見える)

┌ t0 │ t1 │ t2 │ t3 │ t4 ──────┐
│ t5 │ t6 + ────────────────────│
│ content: height = rect.h - 3  │
└───────────────────────────────┘

bar が動的に2行化し content が1行減る(PTY へ自動 resize 通知)。1段目は現行の ┌〜┐、2段目は左右端 │・段間区切り線なし。+ は最終可視タブ(t6)の直後。矢印なし(全タブ可視のため)。

3. 2段でも入りきらない(オーバーフロー) — 矢印スクロール併用

┌‹ t3 │ t4 │ t5 │ t6 │ t7 ─────┐
│ t8 │ t9 + ──────────────────›│
│ content: height = rect.h - 3  │
└───────────────────────────────┘

tab_scroll = 3(t0〜t2 は先頭側に非表示、t10 以降は末尾側に非表示)。‹ は1段目左端(tab_scroll > 0 のとき)、› は2段目右端(末尾側に非可視タブがあるとき)。段数は2で頭打ち(content の犠牲は最大1行)。

4. タブのドラッグ&ドロップ — 行優先の中点判定

┌ t0 │ t1 │ t2 │ t3 │ t4 ──────┐
│ t5 ▼ t6 + ────────────────────│
│ content: height = rect.h - 3  │
└───────────────────────────────┘

ポインタの Y でまず行を確定し、行内は X の中点判定(▼ = この例では t5 と t6 の間に挿入)。行の右端(─ 埋め)より右で離すと「その行の末尾=次行の先頭」。ソートキーは (y, x, index)。

5. 小ペイン(rect.height < 5) — 従来動作へフォールバック

┌‹ t4 │ t5 ›─┐
│ content    │
│            │
└────────────┘

content 2行以上を確保できない高さでは2段化せず、従来の1段+矢印スクロール。

6. リサイズハンドル(変更なし)

ペイン上端リサイズのハンドルは1段目のみ(現行どおり。タブ本体セルはタブが優先)。2段目の ─ 埋めは不感帯で、何にも反応しない。

設定項目

項目型既定値意味
tabs.max_rows(新設)整数2(新挙動が既定ON)タブバーの最大段数。1 = 従来の1段+スクロールに完全復帰。有効値は 1/2 で、3以上は 2 扱い・0以下は 1 扱い。
