エディタタブのファイル名表示と文字数上限緩和 — 仕様視覚レビュー(2026-07-26)

spec.md / decisions.md(同ディレクトリ)で確定した見た目・挙動のモックアップ。タブバーの2段表示(別仕様 20260726-pane-tab-multirow、パッチ0007)とは別件で、本図はすべて1段表示の従来レイアウト上で示す。

1. ファイル名表示(通常時)

┌ main.rs │ config.rs │ 0 + ──────────┐
│ content                             │
└─────────────────────────────────────┘

sidebar_files から Enter で開いたエディタタブは、開いた時点で path.file_name()(拡張子込み)が name にセットされ、最優先で表示される(常時ON・設定なし)。シェルタブ(0)は従来どおり番号のまま。

2. 同名ファイルを複数開いたとき(自動区別なし)

┌ mod.rs │ mod.rs │ 0 + ─────────────┐
│ content                            │
└────────────────────────────────────┘

例: app/mod.rs と ui/mod.rs を開いた状態。仕様として自動区別はしない。区別したい場合は既存の RenameTab で手動リネームする(以後は手動名が優先され、自動名で上書きされない)。

3. 文字数上限の緩和(16 → 設定値、既定24)

旧(16固定):   integration_tes…
新(既定24):   integration_test_helper…
新(短い名前): main.rs                （切り詰めなし・そのまま）

ハードコードの truncate(t, 16) を tabs.max_width(既定24)に置換。上限を超えるときのみ末尾 … で切り詰め。widths/fits(横スクロール・当たり判定)には自動反映され下流改修は不要。

4. 日本語ファイル名の例(文字数ベース・現状踏襲)

┌ 業務要件定義書_最終版.md │ 0 + ────┐

13文字なので24文字上限には収まり全文表示されるが、全角のためセル幅は約24セルと広めになる。カウントは文字数ベース(現状踏襲)で、表示幅(East Asian Width)ベースへの変更は本件の対象外。全角による座標ズレの可能性は RenameTab で日本語名を付けた場合に今も存在する既存制約であり、実害が出たら別件として扱う。
