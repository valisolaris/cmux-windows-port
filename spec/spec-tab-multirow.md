# ペイン内タブバーの複数行(2段)表示 — 仕様書

最終更新: 2026-07-26(視覚レビュー承認により凍結。実装引き継ぎは handoff.md)

## 目的

cmux-tui のペイン内タブバーは現在1行固定で、タブが入りきらない場合は `‹`/`›` 矢印による横スクロールになる。複数ファイルを1ペインに統合してタブで扱うと、見えないタブが増えて不便。**タブがペイン幅に入りきらないとき、タブバーを2段(複数行)に折り返して表示できるようにする**のが本仕様の目的。

ユーザー要望(要約): 「すべて見えなくてもいい。いまより少し広い範囲でタブが見えればいい。タブがペイン内でいっぱいになると2段表示とかになるとなおいい」

## スコープ

### やること
- タブ溢れ時のタブバー複数行化のレイアウト設計(content 領域・PTY リサイズとの整合を含む)
- クリック / タブのドラッグ&ドロップ / ペインリサイズハンドルの当たり判定の設計
- 新設定項目の設計(名前・型・既定値)
- 既存テストへの影響整理とパッチ分割方針

### やらないこと(別軸・対象外)
- **タブ名をファイル名にする件**(`tab_label()` / `show_titles` 系)— 別軸で合意形成中
- **表示文字数16文字上限(`min_width` 系)の緩和** — 同上
- 本仕様では現行のラベル生成ロジックをそのまま前提とする(ラベル幅が変わっても本設計は成立すること)
- Zellij 風スタック表示(折りたたみペイン、`stacked_header_parts_for_rect`)の挙動変更 — bar=rect 全体という別モードであり今回は触らない

## 前提(現状のコード事実)

Explore 済み(再調査不要)。対象: `cmux/cmux-tui/crates/cmux-tui/src/ui/pane.rs`、`.../src/app.rs`、`.../src/config.rs`。

1. **PaneArea**(app.rs:2254-2269): 各ペインの1フレーム分の描画領域。`bar: Option<Rect>`(タブバー行。None なら狭すぎて非表示)、`content: Rect`、`track: Option<Rect>` を持つ。
2. **pane_parts_for_rect**(app.rs:3256-3297): `rect.width > 2 && rect.height > 2` のとき `bar = Some(Rect { height: 1, ..rect })`(常に1行・rect 上端)、`content.height = rect.height - 2`(定数 2 = bar 1行 + 下枠1行のハードコード)。狭すぎる場合は `bar: None, content: rect`。
3. **stacked_header_parts_for_rect**(app.rs:3298 付近): 折りたたみペインは `bar: Some(rect)`(ペイン全体がバー)、`content.height: 0`。「bar は1行固定」ではないパターンの既存前例。
4. **App::sync_layout**(app.rs:5230-5374): 毎フレーム、split 木 → 生 Rect → `pane_parts_for_rect` → PaneArea を作り直す。content サイズが変われば PTY(ghostty-vt)に resize を自動通知(`enqueue_surface_resize`/`attach_surface`、app.rs:5341-5372)。**bar を2行にして content を1行減らすことは既存パイプラインにそのまま乗る**(新しい resize 配線は不要)。ペイン分割リサイズ(app.rs:9746-10048)も次フレームの sync_layout 任せで問題なし。
5. **draw_tab_bar**(pane.rs:163-335): bar 行に `┌` + タブラベル + ` + `(新規タブ)+ `─` 埋め + `┐` を描画。溢れは `tab_scroll`(先頭インデックス)+ `‹`/`›` 矢印の横スクロールで対処(折り返しではない)。
6. **draw_box**(pane.rs:116-158): 左右下枠と4隅を描画。上端行(bar.y)には触れない(コメントで明記)。`draw_all`(pane.rs:88-112)で draw_box は常時、draw_tab_bar は `area.bar.is_some()` のときのみ。
7. **クリック当たり判定**: `Hit` enum(app.rs:2138。`Tab` 2183-2186、`NewTab` 2187-2189、`TabScroll` 2206-2209)。`app.hits` は毎フレームクリアし draw_tab_bar が push(pane.rs:334)、`hit_at(x,y)`(app.rs:8269-8271)が最初にマッチした Rect を返す。Rect ベースなので2段化しても hit_at 自体はそのまま使える。
8. **タブ D&D**: `Drag::TabArm`/`Drag::Tab`(app.rs:2884-2932)。ドロップ先判定 `tab_drop_target_at(x,y)`(app.rs:8287-8315)は `sort_by_key(|(rect,index)| (rect.x, *index))` と **X 座標だけ**でソートし Y を見ない。「同じ X・違う Y(2段目)」を区別できないため、2段化ではここの並べ替え・中点判定の改修が必須。
9. **上端行のリサイズヒット**: `push_resize_hits`(pane.rs:498-536)が上端行全体に `Hit::PaneResize{vertical: Some((pane, PaneEdge::Top))}` を敷く(526-529)。タブの隙間(`─` 埋め)は現状ペイン境界のドラッグリサイズハンドルを兼ねる。タブ本体セルは呼び出し順(pane.rs:88-112)によりタブが勝つ。
10. **既存テスト**: `alt_n_uses_zellij_default_vertical_distribution`(app.rs:10854、10911-10930)が `bar == Rect{height:1,..}` と `content.height = rect.height - 2` を直接 pin。`browser_omnibar_reduces_content_rect_for_graphics_and_input` 等(11257 以降)も同様。`PaneArea` リテラルを `bar: Some(Rect{...height:1,...})` で直書きする fixture が複数(11317, 11470, 11647, 11697, 14059, 14109, 14209)。2段化でこれらの更新・監査が必要。
11. **Tabs 設定スキーマ**(config.rs:642-666): `min_width`/`solid_background`/`show_titles`/`agents` のみ。行数・折り返し関連の項目は無い。新設定はここに追加する。
12. **リポジトリの位置づけ**: 本リポジトリは Windows 移植パッチ集。一般 UX 改善を新規パッチとして追加すること自体は前段の会話で確認済み(Phase 4/5 に前例あり)。

### 設計上の自明事項(質問にしない前提)
- 折り返しはタブ境界で行う(ラベルの途中で改行しない)。
- 2段化しても `hit_at` は Rect の集合を順に見るだけなので、各タブに正しい Rect を push すればクリック判定は成立する(改修が要るのは D&D の並び順ロジックのみ)。

## 確定事項(Round 1、経緯は decisions.md)

- **(a) 段領域の確保方式 = 動的2段化**: タブが溢れたときだけ bar を2行にし、content を1行減らす。タブ増減時の content 高さ変動と PTY resize はトレードオフとして受け入れ済み。
- **(b) 小ペイン時 = content 2行以上残るときのみ2段化**: 閾値 `rect.height >= 5`(bar2+content2+下枠1)。未満は従来の1段+矢印スクロールへフォールバック。
- **(c) 最大段数 = 2段上限**: 2段でも入りきらない分は既存の `tab_scroll` + `‹`/`›` 矢印スクロールを2段レイアウト上で併用。
- **(f) 設定 = `tabs.max_rows` 新設・既定値 2**(新挙動が既定ON)。`1` で現状の1行+スクロールに完全復帰。config.rs:642-666 の `Tabs` に追加。

## 確定事項(Round 2、経緯は decisions.md)

- **(d) D&D = 行優先の中点判定**: ポインタの Y でまず対象行を確定し、行内は現行同様 X の中点判定(既存ロジックを行内で再利用)。行の右端より右でのドロップは「その行の末尾=次行の先頭」と同義。`tab_drop_target_at`(app.rs:8287-8315)のソートキーを `(rect.y, rect.x, index)` に変更。
- **(e) 2段目の隙間 = 不感帯**: `push_resize_hits`(pane.rs:498-536)は現状のまま上端行(1段目)のみに `PaneResize` を敷く。2段目の `─` 埋めは何にも反応しない。
- **`+`/矢印の配置**: `+` は最終可視タブの直後(現行踏襲)。`‹` は1段目左端(`tab_scroll > 0` のとき)、`›` は2段目右端(末尾側に非可視タブがあるとき)。
- **(g) パッチ = 1パッチ+テスト更新同梱**: レイアウト・描画・当たり判定・設定・既存 fixture 更新(app.rs:10854、10911-10930、11257 以降、11317、11470、11647、11697、14059、14109、14209)を1つの自己完結パッチに。規模は中規模(数百行)見込み。
- **段間の視覚デザイン(仮案を確定)**: 1段目は `┌`〜`┐`(現行)、2段目は左右端を `│` で描き、段間に区切り線は入れない。分担は「bar 領域(高さ bar.height)は全セル draw_tab_bar 担当、draw_box(pane.rs:116-158)は bar 領域に触れない」と現行ルールを高さ方向に一般化する。
- **スクロール状態(仮案を確定)**: 既存 `tab_scroll`(先頭可視タブのインデックス)を2段レイアウトでもそのまま流用。意味論は現行と同一(`‹`=戻る、`›`=進む)。
- **(f) の派生仕様**: `tabs.max_rows` の有効値は 1 または 2。3以上を指定した場合は 2 として扱い(2段上限の決定による)、0 以下は 1 として扱う。
