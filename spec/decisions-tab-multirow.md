# 決定ログ

ラウンドごとに「質問 / 回答 / 採用理由 / 捨てた選択肢」を追記していく。

## Round 1(2026-07-26)— 4問とも推奨案で確定

### Q1. 段領域の確保方式 → 動的に2段化
- 回答: タブが溢れたときだけ bar を2行にし、content を1行減らす。
- 採用理由: 要望「いっぱいになると2段」に最も合致。既存の sync_layout → PTY resize パイプライン(app.rs:5230-5374)にそのまま乗り、新規配線が不要。
- 受け入れたトレードオフ: タブ数の増減で content 高さが1行変わり、PTY resize・再描画が走る。
- 捨てた選択肢: 常時2行予約(タブが少ないとき1行が常に無駄)/設定で固定切替(「溢れたら2段」という要望から離れる)。

### Q2. 最大段数と超過時の挙動 → 2段上限+矢印スクロール併用
- 回答: 最大2段。2段でも入りきらない分は既存の `tab_scroll` + `‹`/`›` 矢印スクロールを2段レイアウト上で併用。
- 採用理由: 「すべて見えなくてもいい」という要望に合致。content の犠牲は最大1行、実装・テストの複雑さも最小。
- 捨てた選択肢: N段(設定値)(content 圧迫・複雑化)/無制限折り返し(content 消失リスク、要望に対しオーバースペック)。

### Q3. 設定項目と既定値 → `tabs.max_rows` 新設・既定値 2(既定ON)
- 回答: config の `Tabs`(config.rs:642-666)に `max_rows`(既定 2)を追加し、新挙動を既定有効に。`1` で現状の1行+スクロールへ完全復帰(オプトアウト可)。
- 採用理由: ユーザー自身の要望機能なので既定ONが自然。従来動作へ戻す経路を確保。
- 捨てた選択肢: 既定1・オプトイン(自環境で毎回設定が必要)/設定なしで常時ON(戻す手段が無い)。

### Q4. 小さいペインでのフォールバック → content 2行以上残るときのみ2段化
- 回答: 閾値 `rect.height >= 5`(bar2+content2+下枠1)。未満は従来の1段+矢印スクロールへフォールバック。
- 採用理由: content 2行がシェル操作の実用最低ライン。
- 捨てた選択肢: content 1行でも2段化(ほぼ操作不能)/content 4行以上のみ(恩恵が大ペイン限定)。

## Round 2(2026-07-26)— 4問とも推奨案で確定

### Q1. D&D 行またぎドロップの意味論 → 行優先の中点判定
- 回答: ポインタの Y でまず対象行を確定し、行内は現行同様 X の中点判定。行の右端より右は「その行の末尾=次行の先頭」と同義。`tab_drop_target_at`(app.rs:8287-8315)のソートキーを `(rect.y, rect.x, index)` に変更。
- 採用理由: 挙動が予測しやすく、既存の中点判定ロジックを行内で再利用でき差分最小。
- 捨てた選択肢: 全体一列の最近傍判定(余白で遠い位置が選ばれ予測しにくい)/2段表示中の D&D 無効(機能退行)。

### Q2. 2段目とリサイズハンドル → 不感帯(リサイズは最上段のみ)
- 回答: `push_resize_hits`(pane.rs:498-536)は現状のまま1段目のみ。2段目の `─` 埋めは何にも反応しない。
- 採用理由: 「ペイン境界の線を掴んで動かす」という物理的メタファーに一致し、実装変更ゼロ。
- 捨てた選択肢: 2段目もハンドル化(境界でない行のドラッグで上端が動くのは直感に反する)/タブスクロール操作の割当(オーバースペック)。

### Q3. `+` と `‹`/`›` の配置 → `+` は最終可視タブ直後、`‹` は1段目左端・`›` は2段目右端
- 採用理由: 現行「タブ列の直後に `+`」の自然な拡張。矢印の物理位置とスクロール方向が一致(左へ戻る `‹` は先頭行の左端、右へ進む `›` は末尾行の右端)。
- 捨てた選択肢: 操作系を2段目右端に集約(`‹` が方向と逆)/`+` を1段目右端に固定(タブ表示領域を常時消費)。

### Q4. パッチ分割 → 1パッチ+テスト更新同梱
- 採用理由: レイアウト・描画・当たり判定・設定・fixture 更新は相互依存が強く中間状態が壊れるため、分割の利得が薄い。「各パッチ単体でテストが通る」というパッチ集の流儀に合う。規模は中規模(数百行)見込み。
- 捨てた選択肢: 2パッチ分割(既定ON決定と噛み合わせる細工が必要)/本体とテストの分離(自己完結の原則に反する)。

### 司令塔仮案の確定(team-lead 承認により質問ラウンド省略、視覚確認は review.html で実施)
- 段間の視覚デザイン: 2段目は左右端 `│`・段間区切り線なし。「bar 領域(高さ bar.height)は draw_tab_bar 担当、draw_box は bar 領域に触れない」と現行分担を高さ方向に一般化。
- スクロール状態: 既存 `tab_scroll`(先頭可視タブのインデックス)をそのまま流用。意味論は現行と同一。
- (f) 派生仕様: `tabs.max_rows` の有効値は 1/2。3以上は 2 扱い(2段上限による)、0 以下は 1 扱い。
